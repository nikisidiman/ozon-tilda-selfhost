# Устройство кода — для разработчика и ИИ-агента

Сервис для одного магазина. Виджет (`widget/w.js`) встраивается в корзину Tilda и спрашивает у сервера цену доставки Ozon до выбранного пункта выдачи. Вебхук Tilda (`routes/hook.ts`) создаёт отправление в кабинете Ozon Доставки магазина. Каждый входящий вебхук пишется в таблицу `hook_log` (результат и тело, замаскированное `maskPersonal` из `lib/tilda-order.ts`, 30 дней); его показывает `ozon-tilda logs`.

Код перенесён из многопользовательской версии, поэтому в базе остались таблицы `users`, `sessions` и `consent_events`. Нужна из них только одна служебная запись в `users`: на неё ссылается `shops.user_id`. Магазин всегда один, первая строка `shops`.

## Устройство

- `server/src/main.ts` — HTTP-сервер (Hono). Все пути начинаются с `/ozon-tilda`: `/health`, `/w.js`, `/api/w/*` (виджет), `/api/hook/tilda/:token` (вебхук).
- `server/src/routes/widget.ts` — API виджета: `config`, `cities`, `pvz`, `quote`, `check-phone`, `status`.
- `server/src/ozon/` — клиент Ozon Delivery API:
  - `client.ts` — токены и запросы;
  - `quote.ts` — расчёт цены с кешем;
  - `origins.ts` — метод доставки для города отгрузки;
  - `pvz-sync.ts` — справочник пунктов, обновляется каждую ночь;
  - `orders.ts` — создание отправлений.
- `server/src/lib/price.ts` — цена для покупателя: наценка, порог бесплатной доставки, страховка.
- `server/src/shop-settings.ts` — чтение и запись настроек магазина.
- `server/src/cli/setup.ts` — команды `setup` (шаги 2–4 и 6–10, `--steps 2,3,4` — только выбранные, `--auto` — добавить обязательные незаполненные), `summary` (что настроено), `show`, `check` и `logs`. Шаги 1 и 5 (пишут .env), вступление и меню выбора шагов — в `deploy/ozon-tilda`. Действия в Tilda (код, вариант доставки, вебхук, публикация) мастер объясняет и отмечает в `shops.wizard`.
- Габариты отправления (`ozon/orders.ts`): если у всех товаров корзины в Tilda есть габариты и вес (поле `ozon_parcel` от виджета), отправление создаётся по ним, иначе по типовой коробке магазина (`box_*_cm`, `box_weight_g`). Источник пишется в `shop_orders.dims.source` (`items` / `shop`). Цена в корзине всегда считается по типовой коробке.
- `deploy/ozon-tilda` — bash-обёртка, она же `/usr/local/bin/ozon-tilda`. Шаги 1 и 5 (адрес сервера и ключи Ozon) спрашивает сама и пишет в `.env`, остальное передаёт в `cli/setup.ts` внутри контейнера. `ozon-tilda update` — `git pull --ff-only` и пересборка.
- `install.sh` (в корне) — первая установка на чистый сервер: git, клон в `/opt/ozon-tilda`, затем `deploy/install.sh`.
- `deploy/install.sh` — Docker, `.env` с генерированными секретами, сборка и запуск; повторный запуск безопасен.
- `db/migrations/*.sql` применяются по порядку при старте. Новую миграцию добавляйте файлом со следующим номером, старые не меняйте.

Ключи Ozon лежат в двух местах:
- в `.env`: ими считается цена и грузится справочник;
- в `shops.ozon_*` в зашифрованном виде (ключ шифрования `SHOP_KEYS_KEY`): ими создаются заказы и проверяется номер покупателя.

Копию в базе обновляет `ozon-tilda setup` или `ozon-tilda check`.

## Проверка

```bash
npm ci
npm run typecheck
npm test
```

Пересборка на сервере: `sudo bash deploy/install.sh`.

Без ключей (`OZON_MODE=mock`) сервис работает с тестовыми ценами и десятком условных пунктов из `ozon/mock-pvz.ts`.

## Правила

- Секреты из `.env` не выводить в журнал и на экран.
- Данные покупателей не хранить: у номеров телефонов только HMAC (`shop-keys.ts`), у IP в журнале отрезан последний октет.
